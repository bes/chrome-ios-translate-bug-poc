Chrome for iOS injects the Google Translate library twice into the same page, after which it throws "Maximum call stack size exceeded" on every DOM change

How to reproduce

  1. Use a device whose Chrome for iOS user-interface language is not English, or enable "Always translate English" in Chrome settings under Languages. The Google app on iOS shows the same behavior.
  2. Open this page. When Chrome offers to translate it, accept. The diagnostics panel will report "Translation detected".
  3. Tap "Autopilot" below and wait for a minute or two. The page will navigate between its views every few seconds. Alternatively tap the view buttons yourself, type into the sign-in field, or use Chrome's translate bar to show the original text and translate again.
  4. Watch the diagnostics panel. Once the translate library has been injected a second time, every DOM change produces RangeError: Maximum call stack size exceeded. The error's filename is the URL of this page rather than a script URL, which marks it as coming from a script that Chrome evaluated natively.
  5. Tap "Copy log" and paste the text into the bug report.

If nothing happens, the first translation probably finished within Chrome's 8-second limit, so Chrome considers the page translated and does not translate it again on navigation. The second injection needs a second translation of the same document. Ways to get one:

  • Open Chrome's translate menu for this page, choose "Show original", then choose the target language again. Or switch to a different target language. Every translate action injects the library again.
  • Make the first translation time out: open "Catalog (heavy)" below, then translate. The view has about a thousand unique product descriptions, which usually takes longer than 8 seconds on a phone. Chrome reports that the page could not be translated; then navigate or tap translate again.
  • Or cut the network for ten seconds right after tapping translate (airplane mode), then reconnect and navigate.
